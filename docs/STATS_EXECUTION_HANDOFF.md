## 工作包一：離線完成能審查的開跑準備

現在即可做完此包，不需要逐項請使用者確認。**這一包尚不呼叫付費教師、不啟動 GPU**，因為新方向的資料量、支出與更新預算、逐類目標尚未決定；本次交接沒有把它們假裝成已凍結參數。

1. **建立教材覆蓋表與小批候選。**列出歷史八類、四類組合及四事件的概念對應與重疊；加入單位、條件順序、敘述、數字表示、混淆所求量等欄位。先準備約 100 個可獨立核對的故事及教師請求草案。保留同故事概念對照；不要只複製模板換數字，也不再另開排序實驗。
2. **先分割、再生成。**每筆保留 story_id、模板／改寫血緣、concept、split、來源及雜湊；同故事及其改寫／參數變體不得跨分割。已曝光測試作回歸集，新的保留測試不能交給訓練資料生成器。不要把舊錯題數字或答案直接補進教材。
3. **沿用教師管線，加好可恢復執行與限額。**固定 Llama 教師實際模型 ID、生成參數、每批數量與重試上限；保存原回答、獨立核對結果、拒收原因、用量及成本。若需要當前價格，從官方來源核實。先提出有上限的 pilot／完整批次估算，quota 多不等於沒有成本上限；不要暗中換成其他來源模型。
4. **修好評分與驗證覆蓋。**用獨立開發例驗證等價式、合法執行格式、漏 `/60`、漏變異數項及事件集合。保持「數學正確」與「可執行」兩個欄位，不替答案補缺項。選 checkpoint 前即解決會改變門檻的語義判分；原本 0 分的 moment 驗證不能代表組合能力受到保護。
5. **準備兩起點執行程式。**重用已有 QLoRA／資料 masking／直接 PEFT 驗證流程；加入真的在線上驗證與停止，不能先訓完整輪才挑半輪。設相同新增 token／更新上限、驗證時點與選點規則；記錄實際曝光量。未決參數須明確標記，程式不能用隱藏預設值直接開跑。
6. **提交一頁開跑方案。**列出教材各格數量、教師來源與上限、四次 run 的資源估算、更新及 token 上限、驗證頻率、逐類目標／容許下降、停止規則、測試題數與判分方式。沿用既有參數時說明依據；不要順手調 learning rate、rank、loss 權重或輸出介面。離線驗證資料格式、分割與關鍵 grader 案例即可，不跑大套無關測試。

第一個高階模型決策點：**審核這份具體開跑包，鎖定尚未決定的資料／成本／訓練預算及成功標準。**這是研究設計尚未定案，不是要求使用者重新授權每個例行操作。執行模型要先把可做的準備完成，不能只列問題就停。

## 工作包二：協議定案後，一次完成四個 run

以下依定案協議執行，不需要每個 seed 再請使用者確認。

1. 保存協議、程式、資料 manifest 與 hash，再按限額完成教師 pilot、品質核對及全批生成；pilot 若出現超出協議處理範圍的系統性錯誤，保留證據交回決策，不能靠放寬驗證硬收資料。
2. 使用同一份已稽核教材訓練兩起點×兩個 seed；同一 seed 共用抽樣／排序規則，每次隔離輸出並記錄起點 hash。新 LoRA 指既有原生模型的微調，不是從隨機權重預訓練。
3. 固定驗證保護全部指定能力；首次同時達到新能力及保留目標就停止。達最大更新預算仍未合格就標記失敗，不加第二輪、不換 seed 挑好結果、不增加第五個 run。
4. 只以驗證選 checkpoint；獨立測試只跑已選候選。若無合格點，依事前協議處理診斷候選，不能看到測試結果才挑權重。原始 3B、原 v15 的同場基準只算一次；相同模型 hash、推論設定與題集的結果可快取重用。
5. 每個 run 完成就保存 adapter、config、原始回答、評分、訓練 log、manifest 及 SHA-256；不要等四次都完才備份。每輪只更新一份累積狀態與一份結果摘要，不另開第十份補充報告。
6. 最後交付兩起點×兩 seed 的逐類結果表、配對翻題與共同錯誤、實際 token／updates、耗時／用量，以及可直接選中 ZIP 的下載連結。確認遠端檔名、大小與雜湊，停止 GPU，再回報完成。不能把下載頁開得了當成權重已驗證。

第二個高階模型決策點：**四次結果齊全後，判斷哪個起點達標、是否升級、是否轉短步驟介面／專家路由，或收束文章。**執行模型不自行展開第 22、23 版，也不以單一 seed 或總分掩蓋局部失效。

## 實際找到的問題

| 優先順序 | 證據 | 影響與修正 |
|---|---|---|
| P0：學生拿不到解題條件 | 44 個子題依賴前題：訓練 33、驗證 11。例如 `For that display Y=2*X+17, set up Var(Y).` 的參考答案使用 48，但單題沒有給出 X 的分布或平均數。`build_verified()` 只把單題放入學生 prompt；教師重試也只送 pending 題。 | 每個學生輸入與單題教師重試都必須具備完整情境。可在資料中獨立保存 shared_context，再實際拼進每一筆 prompt；不能只靠同故事相鄰或另一個 batch 傳遞資訊。 |
| P0：分布假設不足 | 12 個 `poisson_process` 首題只有每分鐘到達率，沒有 Poisson／齊次 Poisson 假設，卻把 rate×time 當變異數；其二階動差子題同樣需要該假設。 | 明確補上分布及時間單位，由題目本身決定答案。不能把 grader 能算出參考式視為題目充分。 |
| P1：又把模板數當故事廣度 | 96 個主要是 10 種題型的參數組。表述變化多為加上 `Conditions first:`、`During an operations review` 等外框；`number_form` 標記也未必對應實際文字（分母 100 的事件仍寫成分數）。 | 保留規模，但重新寫實際句式及情境。每類至少兩種訓練表述家族，另留一種驗證表述；真正改變條件位置、事件正反說法或單位表示。按參數、模板／改寫血緣檢查跨分割，不能只檢查唯一 ID。稱為「96 個情境參數組」，直到廣度核對完成。 |
| P1：任務被悄悄改變 | 新 `v18_conditional_wait` 的 8 題問 additional wait；原歷史同類問 conditional total wait。 | 本輪維持 total wait 目標，第二問改成完整條件下的另一種單位／敘述；不把 remaining wait 當同一類已保留，也暫不新增此教學目標。 |
| P1：門檻與資料量不一致 | 4 題的 `both ≥83.3%` 實際要求 4/4；舊弱項被直接要求 50%，卻沒有同場 v15 起始驗證。事件矩陣每類 4 題實際僅兩組參數的兩種說法。 | 改用下方同場基準與整數門檻。抽四個不同事件故事，各問四事件，不把改寫當新增獨立故事。 |
| P1：待複核仍可能通過 | 用明確標示為模擬的 metrics 測 `gate_result()`：一題 pending 且計錯，其餘全對，仍回傳 passed。不是模型實測結果。 | 只要存在會影響決定的 pending，先保存 checkpoint／原文，再完成語義核對後決定；不能把 pending 當錯後直接繼續訓，也不能放行升級。 |
| P1：恢復／實際順序與文件不符 | contract 初次先寫，之後新增 `parent_adapter_sha256`；重啟時用未含此欄位的新 dict 比較，必然不同。訓練雖寫好故事順序，卻沒有 v20 的 OrderedTrainer／SequentialSampler。 | 啟動前完成完整 immutable contract；恢復要核對資料、模型、grader、matrix hash。實際 DataLoader 順序須與保存順序一致，並用離線抽樣測試核對。 |
| P1：保存與曝光保證不足 | `training_complete` 前後未實際打包；只記 rows 的估計上限，沒有 token 計數；接受 corpus 只檢查非空與 reference_conditioned，未核實每列來源。 | 每列核對 question hash、split、teacher raw／判定；記 input／supervised tokens 與實際抽樣。adapter／恢復 checkpoint 核對成功後才寫完成標記；最後 ZIP、manifest 及雜湊要真的產生。恢復不能把未完整保存的評分當完成。 |

目前 10 項測試驗證了部分格式及算式，但沒有覆蓋上述主要資料與流程風險。因此「工作包一完成」應改為「草案已提交、審核要求修正」，不能等同開跑就緒。

## 五項研究決策

**1．教材規模與 pilot：採用規模，修正內容。**維持 96 個情境參數組、71 train／25 validation、最多 198 個新訓練目標及 70 個驗證目標，混入固定 192 筆歷史教師 replay；268 不是新訓練列數。兩起點共用同一份接受後 corpus。pilot 保留 24 個訓練故事／65 個目標，不送新測試。

pilot 最多兩次內容嘗試後，接受至少 59/65（90% 向上取整），且每個 archetype 的目標接受率至少 80%（向上取整）。首次接受率另報，不靠未解決的 pending 降低分母。題目條件不足、漏分布假設、洩漏等資料問題必須為零。整批完成也要求每個目標類別接受至少原配置的 80%；避免教師只成功回答容易題，導致完整教材失去最需要教的部分。這是事前工程門檻，不是已知最佳比例。

**2．教師成本：採用 US$0.50 pilot、US$3 累計上限。**教材仍最多 192 calls，pilot 包含在內；另保留 24 次單題教師 benchmark 呼叫，總 call 上限 216、總金額仍 US$3，不重置帳本。pilot 全通過才自動進 full；成本、未明確完成的 request 及重試以持久帳本處理。預留下一次最壞成本再送出，不能用「目前尚未超額」當硬上限；provider 價格上限與 token 限制需保存。這些是支出上限，不是即時價格估算。

**3．訓練預算：一次完整曝光，最多 49 updates。**390/8 向上取整是 49；原 48 上限可能漏掉最後六列。每個 run 的實際上限為 `ceil(accepted_train_rows/8)`，不超過 49、不循環補步。最後不足 8 筆的 batch 正確記錄。兩起點共用資料與實際序列長度；設定 one-pass 的 token 總量，按真正讀到的 input／supervised tokens 記帳。LoRA、LR、precision 延用既有設定，不加調參線。

選點只在第 12、24 及最後一步（去重）驗證，最多三次；首次**已檢查**且同時達標的點即停。停止前完成評分核對。若無合格點，只保留最後點作 diagnostic。這是降低驗證成本的明確取捨，不能宣稱觀察到每一步的首次過關。

**4．停止與升級門檻：取代原百分比清單。**不以「原始 3B 自己較弱的基準」放寬門檻；兩條路都對照同一原 v15。先完成原 v15 的同場驗證，然後按下列固定公式產生整數門檻，不能看到候選結果才改。

| 驗證組 | 規模 | 選點規則 |
|---|---:|---|
| 舊八類 | 48（每類 6） | 相對同場 v15：每類最多失 1，總分最多失 2；下限截為 0。 |
| 組合四類 | 48（每類 12，四故事×三深度） | 每類最多失 1，總分最多失 2；各類 depth 3 子集不得比同場 v15 低。 |
| 新教材事件驗證 | 16（四個不同驗證故事×四事件） | 每種事件至少 3/4，合計至少 14/16。 |

選點共 112 題。去掉原本每新類只抽一題、再用總分作門檻的 19 題組。數學正確／可執行／嚴格格式分開記；學習與保留門檻使用「數學正確且可執行」，並用凍結的格式契約。既有等價式必須在選點前由獨立開發例加入本輪 grader，不去改寫歷史版本的凍結 grader 或成績。未判定項先完成複核，不能用數值相同直接當作結構正確。

最終升級還必須：兩個 seed 都通過選點；在新 288 題同場測試，舊八類合計最多失 4/96、每類最多失 2/12；四組合合計最多失 4/96、每類最多失 2/24。事件 exactly_one 至少 18/24 且比 v15 多對至少 4；四事件至少 72/96 且比 v15 多對至少 8。永久 MC 最多比同場 v15 失 4/240，**122 只有基準實際為 126 時才成立**。若事件基準已接近滿分而沒有足夠 headroom，標記「既定增益門檻不可達」，不要事後改成成功。以上是操作門檻，不是統計顯著／等效性證明，也不代表全部題型已熟練。

**5．最終測試：保留 288＋240 的設計，加 24 題教師對照。**新題、split 及 family/lineage 規則須在付費 pilot 前生成並保存 hash；每個測試 prompt 本身可解、措辭與故事血緣不進訓練。對教師 benchmark 先指定 24 題：舊八類各 1、四組合各 2、四事件各 2；從同一套 holdout 預先固定選出，等 corpus 封存後才送教師，只作比較，禁止回填教材或用來重試教師教學。原始 3B／v15／學生在同一子集的答案取自全套測試。

新測試作廣度檢驗；歷史資料僅作 regression，不能把試過的題再稱新盲測。採固定數據與 raw 回答快取；只有驗證選出的／預定 diagnostic checkpoint 做最終評估，不回頭選最高分。保留 60 題四種排列的永久 MC，不能把它當 240 個獨立觀察。

最壞規劃：四次訓練×三次選點×112＝1,344 次學生生成，加原 v15 選點基準 112 次；六個模型狀態的最終測試最多 3,168 次，共 4,624 次學生生成，另 24 次教師 benchmark。這是無可重用快取的上限，不是執行時間承諾。使用相同固定批次推理設定提高效率；計時／量化相容先測一次後所有 run 共用。

## 給中階模型的下一段工作

1. 依上表修資料、實際 prompt、distribution、total wait、真實表述及 split；重新生成所有衍生檔案。舊 draft hash 保留為歷史。
2. 補上與上述錯誤直接相關的離線檢查：單題與 retry 條件完整、獨立公式／分布核對、實際 DataLoader 順序、contract 重啟、pilot→full gate、pending 不放行、token／資料上限、hash 與保存完整性。不要再增加只對 reference 自我比對的測試來湊數。
3. 新建本輪 grader／selection gate 以隔離歷史判分；所有 code、資料、holdout、grader 的 hash 放入 execution contract。最終 evaluator、teacher benchmark 與打包命令在 GPU 開跑前準備完成。
4. 修正通過後，將本輪核准規則實作進 configuration，保存機器可讀 readiness 結果，再按既有授權跑 pilot。不要只是把三個 status 字串改成 frozen 就略過修正。
5. pilot 達門檻後自動生成全批；資料逐類接受 gate 達標後按本協議完成四次 run、評估、ZIP 保存與 GPU 停止。一般工程錯誤自行處理；若需要放寬這份規則、pilot 教師品質不足或四次結果完成，才交回研究決策。

本審核沒有要求使用者再批准上述例行修正。現在停在 review 交付，是依使用者的模型分工；尚未聲稱修正已完成，也未開啟教師／GPU。

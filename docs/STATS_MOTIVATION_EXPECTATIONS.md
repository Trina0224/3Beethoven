# 從版本成績回到教學假設：v15–v18 的動機、預期與轉折

這份紀錄保留「為什麼做下一版」，不只保留「下一版得幾分」。本次詳細核對 v15–v18，並追溯更早的列式計畫；不宣稱所有早期版本的發想均已完整恢復。

**紀錄性質：2026-09-06 PDT 的回顧整理。** 整理時 v18 的訓練與驗證已完成，主要測試正在進行。因此必須分開辨認：實驗前已提交的文件、今日依文件重述的預期，以及使用者今日補充的發想過程。本文不是把全部敘事重新包裝成事前註冊。

## 使用者補述的轉折

使用者在本次對話說：

> 我是看了15，16，17 我才想到忘了把題目分成從簡單到難而且有關係的順序。因為對小模型來說是有意義的。

這段補述應保留為研究者對發想過程的回顧，不改寫成我們一開始就完整提出並驗證了這個理論。使用者先前在同一對話已明確提出：先教一次概念轉換，再加入兩次並保留一次題，接著加入三次；階段之間存 checkpoint，觀察能力何時出現。

## 我們其實寫過什麼，又沒有落實什麼

更早的列式計畫原文已寫：

> 先在驗證集確認前兩層穩定，再加入兩個已教概念的組合。

這句可在 [原始計畫提交 fd74e1e](https://github.com/Trina0224/3Beethoven/blob/fd74e1e95bd5cd057ac102910486c6de1d0a18ab/docs/STATS_GROUNDED_FORMULATION_PLAN.md) 中核對，並非 v18 結果出來後才加上。可是「計畫提過分層」不等於「實驗已執行按概念深度分階段學習」。

- v13 把不同題型放在同一訓練集，沒有按深度驗證後逐階放行。
- v15 加入平均數、變異數等中間量題目，但仍一起訓練，沒有一次、兩次、三次轉換的獨立進階條件。
- v16 確實分階段；分的是「完整公式提示 → 所求量提示 → 無提示」，不是概念組合深度。
- v17 比較權重混合與均衡複習，沒有實施概念深度排序。
- v18 才把這項原則具體化為深度分組、保留簡單題、驗證停止條件、階段 checkpoint，以及相同實際練習量的打亂順序對照。

實作依據為各版訓練程式：`run_stats_v0_13.py`、`run_stats_v0_15.py`、`run_stats_v0_16.py`、`run_stats_v0_17.py`、`run_stats_v0_18.py`。這條「計畫原則曾存在，後來才轉成可檢查排程」的落差，本身就是值得寫入文章的研究過程。

## 不應混成同一件事的四個假設

以下是本次回顧將想法整理成可檢驗問題，不宣稱四項都在訓練前以這些文字註冊。

1. **概念分解與關係清楚的教材可能有助學習。** 本輪兩個訓練組都使用這種教材，因此不能只憑兩組進步，就分離出教材結構本身的因果效果。
2. **由簡到難的順序可能比打亂更有效。** 這由相同起點、教材曝光量與更新步數的對照檢驗；若兩組接近，就不能宣稱排序優勢已成立。
3. **保留簡單題可能有助維持既有能力。** 本輪沒有另做「完全不複習」組，因此複習是設計中的防護措施，不是已獨立證明的機制。
4. **階段 checkpoint 可以讓能力變化的時間更清楚。** 這能直接觀察模型何時開始答對某類題，但不能據此宣稱讀到了模型內部的推理步驟。v18 的一階驗證在起點已是 16/16，尤其不能說一階能力是在第一階段才長出來。

「概念組合值得研究」與「這個順序已被證明更好」是不同強度的陳述。即使順序對照沒有顯著優勢，發想、預期、實驗落差與對照結果仍然構成有意義的研究敘事。

## 可用於文章的動機段落草稿

回看 v15、v16 與 v17，我們逐漸把問題從「哪一個版本的分數比較高」，移回「我們究竟如何把概念交給小模型」。前幾輪分別嘗試拆出中間量、逐步撤除公式提示，以及混合兩個版本的能力，但這些做法並不等同於先建立基本概念，再逐階增加概念組合深度。使用者因此重新提出：教材不只要有難易之分，題目之間也應有可追蹤的邏輯關係。這項原則其實曾出現在早期計畫，直到 v18 才被落實為一次、兩次、三次概念轉換的訓練排程。我們預期這樣能讓基本能力維持穩定，並更清楚地觀察組合能力在哪個階段改善；同時保留早期題目與階段 checkpoint，另設相同教材和訓練量的打亂順序對照，讓結果有機會推翻我們對順序的直覺。這段歷程的價值，在於把動機、預期與實際證據分開記錄，而不是把最後的分數寫成一條早已知道答案的路徑。

## 後續每版在執行前留下的最小紀錄

| 欄位 | 要寫什麼 |
|---|---|
| 觸發觀察 | 哪一版、哪個同場比較或錯誤案例引出新問題；附原始來源 |
| 動機與來源 | 為什麼現在改；使用者發想、文獻或診斷各自標明 |
| 預期 | 希望哪項能力往哪個方向改變；哪種結果會削弱這個想法 |
| 可檢驗設計 | 變動因素、保留因素、對照組、題集分離與能力範圍 |
| 決策規則 | 停止條件、checkpoint 選擇、成功門檻、預算與保留能力門檻 |
| 時間與修訂 | 執行前提交；途中變更另記時間與當時已看到的資料，不覆寫原預期 |
| 結果後另填 | 實際觀察、未達預期之處、替代解釋，以及為何考慮下一版 |

預期不需要每次猜中；需要的是能辨認它何時提出、如何被檢驗，以及結果之後我們改變了什麼看法。
